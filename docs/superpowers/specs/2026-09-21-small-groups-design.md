# 읽담 소그룹 설계

## 목표

읽담을 개인 서재와 소그룹 인증을 함께 쓰는 앱으로 확장한다. 기존 705권 서재와 그 안의 활동은 기존 소유자만 볼 수 있고, 소그룹에는 사용자가 오늘 인증에 직접 첨부한 짧은 내용만 공유한다.

## 인증과 개인 서재

- 로그인과 회원가입은 Supabase Auth의 이메일·비밀번호 방식으로 제공한다. 이메일 확인 정책은 Supabase 프로젝트 설정을 그대로 따른다.
- 공개 배포에 쓰던 공용 앱 비밀번호는 Auth가 설정된 환경에서는 사용하지 않는다. 계정 인증 전에는 어떤 서재·그룹 데이터도 렌더링하지 않는다. Auth 환경 변수가 없는 로컬 개발 환경만 기존 비밀번호 관문을 유지한다.
- `READDAM_OWNER_EMAIL` Cloud Secret에 기존 서재의 소유자 이메일을 설정한다. 이 이메일로 처음 로그인한 계정이 기존 705권과 활동을 일회성으로 소유하게 된다. 다른 계정은 그 개인 서재와 사진에 접근할 수 없다.
- 새 사용자의 서재 작성 기능은 이번 범위에 넣지 않는다. 새 사용자는 소그룹 화면만 사용하며, 개인 첨부 후보가 없을 때는 텍스트 인증만 남긴다.

## 데이터 구조

기존 `books`와 `activities`에 `owner_id UUID`를 추가한다. 소유자 없는 기존 행은 위의 일회성 소유권 처리로만 채운다.

새 테이블은 다음과 같다.

- `profiles`: Auth 사용자 ID, 표시 이름, 생성일.
- `groups`: ID, 이름, 만든 사람, 생성일.
- `group_members`: 그룹·사용자·역할(`owner`/`member`)·가입일. 한 사용자당 한 그룹에 한 행만 허용한다.
- `group_invites`: 그룹, 충분히 긴 무작위 토큰, 만든 사람, 생성일, 사용 여부. 링크는 `?invite=<token>`을 사용하며 가입이 끝나면 한 번만 소비된다.
- `daily_checkins`: 그룹·사용자·한국 시간 기준 날짜의 고유 조합, 읽음 여부, 한줄소감, 작성일, 선택 첨부의 스냅샷(유형·본문·책 제목·페이지·사진 키). 한 그룹에서 하루 한 번만 작성하거나 수정할 수 있다.
- `checkin_reactions`: 인증·사용자의 고유 조합. 현재 반응은 좋아요 하나다.
- `checkin_comments`: 인증, 작성자, 본문, 작성일.

활동을 첨부할 때 원본 활동 ID는 서버에서 소유권을 검사하는 데만 쓰고, 피드에는 스냅샷만 저장한다. 이후 개인 활동을 수정·삭제해도 이미 공유한 인증의 맥락은 유지한다. 사진은 기존 비공개 Storage의 서명 URL로만 표시한다.

## 권한 규칙

모든 데이터 조회와 쓰기는 서버에서 현재 Auth 사용자 ID를 인자로 받아 검사한다.

- 개인 서재는 `owner_id = current_user_id` 조건이 반드시 붙는다.
- 그룹 목록·피드·인증·반응·댓글은 `group_members`에 현재 사용자가 있는 그룹만 허용한다.
- 그룹 생성자는 owner 역할을 받고, 초대 링크를 만든다.
- 초대 토큰으로 가입할 때만 새 멤버 행을 만들며, 이미 가입한 경우에는 멱등으로 처리한다.
- 한줄소감은 공백 제외 1~280자, 댓글은 1~500자로 제한한다.

## 화면 흐름

1. 첫 화면은 로그인/회원가입이다. 로그인 후 표시 이름이 없으면 한 번만 입력한다.
2. 기존 소유자는 기존 `책장`, `타임라인`, `한 장의 추억`, `통계`, `스트릭`과 새 `소그룹`을 본다. 일반 회원은 `소그룹`만 본다.
3. `소그룹`에서는 내가 가입한 그룹 목록, 새 그룹 이름 입력, 대기 중 초대 링크 가입을 제공한다.
4. 그룹 화면의 `오늘 인증` 폼에는 읽음 체크, 한줄소감, 선택 첨부(내 인용구 또는 사진)와 저장 버튼이 있다. 오늘 이미 작성한 인증은 같은 폼에서 수정한다.
5. 그룹 피드는 오늘 인증을 최신순으로 보여 주며, 표시 이름·시각·읽음·소감·선택 첨부·좋아요 수·댓글을 포함한다. 좋아요는 토글이고 댓글은 즉시 추가된다.

## 오류 처리와 검증

- Auth 실패, 미가입 초대, 만료·사용된 초대, 권한 없는 접근은 사용자에게 이유를 표시하고 데이터를 읽거나 쓰지 않는다.
- 테스트는 SQLite와 Postgres 호환 경로 모두에서 소유권, 초대, 하루 한 건 제한, 첨부 스냅샷, 좋아요 토글, 댓글 권한을 검증한다.
- AppTest는 로그인 전 본문 비노출, 그룹 생성, 인증 저장, 피드, 반응, 댓글 UI를 검사한다. 실제 Supabase Auth에는 별도 테스트 계정을 만들지 않는다.

## 배포 설정

Cloud Secrets에 기존 Supabase 키 외에 `READDAM_OWNER_EMAIL`을 추가한다. 이메일 값은 Git과 문서에 기록하지 않는다. `SUPABASE_ANON_KEY`는 Auth 요청에만 쓰고 서비스 역할 키는 서버 내부 저장소 처리 외에 브라우저로 전달하지 않는다.
