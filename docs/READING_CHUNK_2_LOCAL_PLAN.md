# Reading Chunk 2차 — 예화창고 분류 export 로컬 구현 작업계획

2026-09-28 · Codex · 계획은 아래와 같다. **2026-09-28 로컬 구현 완료; 실제 iCloud export 미실행.** 최신 검증·운영 차단 근거는 [2차 export 프리플라이트](READING_CHUNK_2_EXPORT_PREFLIGHT.md)를 따른다.

## 구현 결과와 사용 경계

- `tools/export_chunk_illustrations.py`는 1차-A `tools/export_chunks.py`와 분리된 명시 CLI다. 읽기 전용 DB 연결을 사용하고 `--owner-id`가 필요하다. `--chunk-id`를 반복 지정할 수 있으며 생략하면 해당 소유자의 Chunk 전체를 선택한다. `--dry-run`은 계획만 JSON 줄로 출력하고 잠금·폴더·manifest를 포함한 파일을 생성하거나 변경하지 않는다.
- 실제 분류 export 전에는 선택한 Chunk의 1차-A `독서조각/` txt·`_index.csv`·`.export-state.json`이 정본과 일치해야 한다. 누락·불일치는 `CONFLICT`로 보고하고 쓰기 실행을 중단한다. 1차-A txt export를 자동 실행하지 않는다.
- 읽담 소유 manifest는 `독서조각/_illustration_manifest.json`이며 버전·소유자와 Chunk별 `category`, `relative_path`, `sha256`, `export_identity`를 기록한다. `_index.csv`의 `예화창고 경로들`에는 같은 경로 집합을 정렬된 JSON 배열로 넣는다. 두 목록이 다르거나 manifest가 손상되면 기존 파일 소유를 추정하지 않는다. 두 exporter는 `.export.lock`을 공유하고 2차는 `.illustration-pending.json`으로 중단 후 같은 소유자/선택에 한해 복구한다.
- 임시 fixture에서 사용한 형태: `python tools/export_chunk_illustrations.py --output-root <임시 루트> --owner-id <소유자 ID> --dry-run`, 이후 같은 명령에서 `--dry-run`만 빼고 실행·동일 실행. 실제 iCloud 루트를 지정한 쓰기 실행은 별도 승인·프리플라이트 전까지 금지한다.

## 계약과 범위

- 읽담 `reading_chunks`가 유일한 정본이다. 예화창고 txt는 언제든 재생성 가능한 파생본이다. 1차-B 운영 연결은 Sites 관리형 D1 `0004`의 공식 적용 경로 확인 대기로 `BLOCKED`이며, 이 로컬 계획과는 독립이다.
- 기존 `tools/export_chunks.py`의 1차-A `독서조각/` txt·`_index.csv` 규칙을 보존한다. 2차는 **별도 명시 실행 경로**에서만 기존 카테고리 `<카테고리>/읽담/`에 사본을 만든다. 1차-A CLI 실행만으로 카테고리 파일을 생성하지 않는다.
- 기존 카테고리를 생성·변경하지 않고 사람이 만든 파일을 읽거나 수정·삭제하지 않는다. 로컬 구현·검증에는 합성 SQLite와 임시 루트만 사용한다. 실제 iCloud 루트 접근·export·배포·운영 DB 변경은 이번 단계의 완료 기준에 포함하지 않는다.
- 최신 공통 계약은 공동 `CROSS_PROJECT_HANDOFF.md`, 상세 매핑은 오늘의 서재 `docs/READING_CHUNK_DESIGN.md` 7.2절과 `docs/READING_CHUNK_2_APPROVAL.md`를 따른다. 나머지 여섯 처리 규칙도 승인안대로 고정한다.

## 확정된 입력과 출력

| 입력·상태 | 로컬 구현 규칙 |
| --- | --- |
| `illustrationTags` | 이 필드만 카테고리 판정에 쓴다. 일반 `tags`나 `contentTypes=illustration`만으로 폴더를 추정하지 않는다. |
| 폴더 이름 | 기존 카테고리 이름 목록만 읽고 NFC 정규화한 **유일한 정확 일치**를 자동 연결한다. 실제 경로에는 디스크의 원래 이름을 사용한다. 부분 일치·쉼표 분해·유사어 추정은 금지한다. |
| 명시 매핑 | `관계`·`공동체`→`공동체,관계, 교회`; `비전`·`열정`→`꿈,비전,사명,열정`; `말씀묵상`→`성경,말씀묵상`; `영생`→`부활,영생`; `하나님나라`→`하나님 나라`. 기존 설계의 `독서조각/_예화창고_태그매핑.csv`(`태그,폴더`) 계약을 사용하되 승인된 연결만 허용한다. |
| 모호성 예외 | `교회`, `사명`, `성경`, `말씀`, `결혼`, `이성교제`는 **정확 일치보다 우선해 미분류**로 둔다. 다른 태그도 대상 후보가 둘 이상이거나 NFC 충돌로 유일하지 않으면 미분류다. 임의 CSV 행으로 예외를 우회하지 않는다. |
| 여러 태그 | 서로 다른 카테고리로 매핑되면 각 카테고리 `읽담/`에 사본 한 부씩, 같은 카테고리로 모인 태그는 한 부만 생성한다. |
| 미매핑·태그 없음 | 카테고리 사본 없이 1차-A `독서조각/` txt만 유지하고 미매핑 결과를 보고한다. `_미분류`나 새 카테고리를 만들지 않는다. |
| 파일명·내용 | 1차-A `filename_for()`가 실제 선택한 파일명과 같은 UTF-8(BOM 없음)·LF txt를 사용한다. 8자리 ID 충돌 시 12자리·전체 ID로 늘린 **실제 index 경로**를 따라간다. |
| 태그 변경·soft delete | `_index.csv`의 `예화창고 경로들`에 기록된 읽담 소유 사본만 정리한다. soft delete 시 카테고리 사본을 제거하고 1차-A 기본 txt의 `_삭제됨` 이동 규칙은 유지한다. |
| 재실행 | 같은 `chunkId`와 동일 상태면 중복 파일이 생기지 않는다. 정본에서 새로 산출한 목적지 집합과 소유 index를 대조한다. |

## 구현 순서와 관문

1. **사전 검증·격리.** 현재 브랜치/작업트리, 공통 계약, 1차-A exporter·테스트를 다시 읽고 변경 소유 범위를 확인한다. 합성 DB와 `tmp_path` 트리만 준비한다. 1차-A `_index.csv` 다섯 번째 열은 현재 보존만 한다는 점을 회귀 기준으로 고정한다.
2. **순수 매핑 함수.** 기존 카테고리 목록의 NFC 중복, 명시 매핑 대상 존재, 모호성 예외 우선순위를 검증하고 `illustrationTags`에서 **서로 다른 기존 카테고리의 집합**을 산출한다. 결과는 디스크 이름과 미분류 태그를 함께 반환한다. 잘못된 CSV, 경로 요소, 중복·충돌은 안전하게 중단하거나 미분류로 보고하되 새 폴더는 만들지 않는다. 이 단계의 단위 테스트가 통과해야 다음으로 간다.
3. **별도 exporter 경로.** `tools/export_chunk_illustrations.py`와 같은 명시 호출 경로를 추가한다. 기존 1차-A archive export가 만든 `_index.csv`에서 owner·`chunkId`·실제 기본 txt 경로를 확인하고 `예화창고 경로들`을 결정적인 정렬 순서의 상대경로 목록으로 기록한다. 목록 인코딩과 소유 파일 digest/복구 기록의 구체 형식은 1차-A 호환성을 확인한 뒤 선택하고 테스트로 고정한다. 기존 `--output-root` 경계·단일 writer lock·symlink/path escape 방어·무소유 파일 no-clobber를 재사용한다. 카테고리 `읽담/`도 **기존 카테고리 안에서만** 만들 수 있다.
4. **변경·삭제·재시도.** 사전 검사에서 index·관리 파일 내용이 기대 digest와 다르면 덮거나 삭제하지 않고 중단한다. 새 사본을 안전하게 기록한 뒤 index/복구 상태를 durable하게 갱신하고, 오래된 경로 중 index가 소유하며 검증된 사본만 정리한다. 중단 후 재실행은 기록된 계획을 복구하며 중복 생성하지 않는다. 비어 있는 **읽담 소유** `읽담/`만 정리한다. 다른 사용자의 파일이 있으면 폴더를 남긴다.
5. **로컬 통합·회귀.** 합성 DB→1차-A 기본 txt/index→2차 분류 복사→태그 변경→soft delete→재실행을 임시 루트에서 끝까지 시험한다. 다중 카테고리, 같은 카테고리로 모이는 태그, 모호한 여섯 태그, 정확 일치/NFD·NFC, 미매핑·무태그, `contentTypes` 단독, 8자리 파일명 충돌, 사용자 파일 보존, 경로·symlink 공격, 중단/복구를 포함한다. 기존 1차-A 테스트 전체와 Python compile, `git diff --check`도 통과해야 한다.
6. **기록과 커밋.** 실제 변경 파일만 stage해 검토하고 의미 단위별 로컬 커밋을 만든다. HANDOFF/WORKLOG에 테스트 수·합성 루트·남은 한계를 기록한다. main/push/배포/실제 iCloud export는 수행하지 않는다.

## 멈춤 기준과 완료 판정

1차-A txt/index 계약을 깨야 하거나, 소유·digest 검증 없이 기존 파일을 지워야 하거나, 승인되지 않은 태그 매핑/새 카테고리/정책 변경이 필요하면 멈춘다. 실패 후 복구가 증명되지 않거나 기존 파일이 예상 밖으로 바뀌어도 멈춘다.

로컬 완료는 **합성 루트에서만** 매핑·다중 복사·소유 파일 정리·멱등성·중단 복구와 1차-A 회귀가 통과하고, 기존 사용자 파일이 불변임을 검증한 상태다. 그 뒤 실제 iCloud 실행은 별도 작업과 승인·프리플라이트가 필요하다.
