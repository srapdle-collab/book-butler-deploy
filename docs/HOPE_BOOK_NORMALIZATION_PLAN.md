# 「희망을 짓는다는 것」 읽기 전용 정상화 계획

2026-09-29 M1 운영 DB `transaction_read_only=on` 조회 기준. **이 문서는 실행 승인이 아니며 DB·iCloud 쓰기와 중복 삭제는 0건**이다.

## 정본과 복원 근거

- David가 보존하기로 결정한 책: `94a4470c-46bc-4a70-9359-c105361bfe6f` (`읽는 중`, `분별력`, 567쪽, ISBN `9788932550817`).
- 기존 독서 세션 `6668f3b6-2f3a-4851-8595-2a9524c5b018`의 `started_at=1790602346` = **2026-09-28 22:32:26 KST**. `stopped_at=1790602464` = 22:34:24 KST, 상태 `stopped`, 연결 활동 없음. 같은 책의 활성 Chunk `b0135692-7893-4f6a-b049-b198f30933a3`는 22:36:31 KST 생성, `read_date=2026-09-28`, 31쪽이다. 따라서 타이머 시작은 실제 기록된 가장 이른 독서 시각이며 Chunk 날짜와도 맞는다.
- 읽는 중 책의 미삭제 활동은 0건이고 `start_date`는 NULL이다. 책장의 정렬은 최근 활동일→`start_date`→0, 이어서 읽기는 상위 6권. 현재 36위다. 세션의 실제 시작 epoch를 `start_date`로 복원한다고 가정한 읽기 전용 순위 계산에서는 이 값보다 최신 정렬값인 읽는 중 책이 **0권**이므로 예상 1위다.

## 최소 변경안 — 미실행

별도 운영 DB write 승인을 받은 뒤, 같은 값과 대상 행 상태를 다시 읽기 전용으로 확인한다. 값이 그대로면 단일 트랜잭션에서 **보존 책 한 행의 `start_date`만 `1790602346`으로 채우는 조건부 UPDATE**를 계획한다. 조건은 `id` 일치, `status='읽는 중'`, 현재 `start_date IS NULL`, 세션이 같은 책에 여전히 연결됨이다. 영향 행이 정확히 1건일 때만 확정하고, 그 뒤 이어서 읽기 상위 6권에 표시되는지 확인한다. 활동을 만들어 정렬을 바꾸거나 세션·Chunk·진도·상태·카테고리를 수정하지 않는다. 값이 달라졌거나 조건이 맞지 않으면 중단하고 재조사한다.

## 위시리스트 중복 — 삭제 후보만 지정

- 후보: `b735496a-3c23-402d-a853-1c30ac2f721d`. 같은 ISBN의 위시리스트이며 카테고리·쪽수·start_date가 없다. `activities`, `reading_chunks`(soft delete 포함), `reading_sessions`, `photo_manifest`, `source_book_state`의 `book_id` 참조는 모두 0건이다. 실제 외래키가 `books(id)`를 가리키는 자식 표는 앞의 처음 세 표뿐이다. 같은 제목의 `daily_checkins.attachment_book_title`도 0건이다. `cover_photo`는 없고 `cover_url`만 있다.
- 현재 확인된 DB 참조와 읽담 관리 파일 기준으로는 삭제가 다른 독서 기록·사진 파일을 건드릴 계획이 없다. **지금 삭제하지 않는다.** 추후 David가 삭제를 별도 승인하면, 직전 재조회·백업·영향 행 1건 조건·트랜잭션 rollback 기준을 먼저 확정한다. 앱 밖에서 URL이나 책 UUID를 보관한 사용자 자료까지 없다고 단정하지 않는다.

## 실제 Reading Chunk 첫 E2E 후보

- 활성 Chunk 2건 중 `97235947…`는 추천·승인 기능 커밋 `276c958`(2026-09-28 15:00 KST) 이전인 2026-09-27 23:19에 생성돼 기존 Chunk에 해당한다. 2026-09-28 22:36에 생성된 희망 책 Chunk는 기능 도입 후 건이다. 기존 규칙은 본문·일반 태그에서 승인 사전 표현을 찾지 못해 추천 0건이었고, `illustrationTags=[]`이며 `updated_at=created_at`이다. 승인 화면을 실제로 봤는지, 건너뛰었는지는 DB에 이벤트가 없어 판별할 수 없다.
- 새 약한 후보 규칙은 기존 63개 카테고리 이름의 **독립 단어**가 본문에 있고 더 강한 후보가 없을 때만 해당 기존 카테고리를 제안한다. 희망 책 Chunk의 `성경`에 대해 `성경, 말씀`과 `성경,말씀묵상`을 각각 점수 1·기본 체크 해제 상태로 제안한다. 기존 강한 후보의 기본 체크와 David의 명시 승인은 유지한다. 자유 입력 예화 카테고리는 없다.
- 운영 DB 값을 바꾸지 않고 두 후보를 **각각 가정한** 실제 예화창고 계획은 해당 기존 카테고리 `읽담/`에 CREATE 1, 기존 파일 UPDATE/DELETE 0이다. 이는 David의 승인 또는 실제 export가 아니다. 승인 후 실제 태그가 저장되면 단일 파이프라인 dry-run을 다시 실행해 대상 경로·충돌·소유 상태를 확인한다. 실제 iCloud export와 launchd는 계속 미실행이다.
